# Multilingual support (German/English)

🇬🇧 **English** · 🇩🇪 [Deutsch](../i18n.md)

Decision 45: **German stays the source language** (msgid). English comes from `.po` files.

## Which language applies?

1. The logged-in user's own language (`Benutzer.sprache`, empty = none)
2. Device cookie `nestwerk_sprache` (DE/EN switch on the start screen, `/i18n/setlang/`)
3. Browser language (`Accept-Language`)
4. Otherwise German (`LANGUAGE_CODE = "de"`)

Without a request (worker, cron, push, email), the recipient's language applies: `translation.override(kern.sprache.fuer(empfaenger))` = own language, otherwise the family language (setting `allgemein.sprache`, taken from the language chosen during setup).

## Default content in the database

Ranks, badges, categories, buttons etc. are created in German. In the seed code they are marked with `gettext_noop` and only translated when displayed: template `{% load sprache %}` + `{{ rang.name|uebersetzt }}`, Python `kern.sprache.uebersetzt(text)`. Texts changed by parents are not msgids and stay unchanged.

## Texts in events

Event data is stored and shown later to different recipients. So do not store finished German sentences there. Store the msgid + parameters instead (e.g. `hinweis_msgid`, `hinweis_parameter`) and translate only when rendering.

## Where are the translations?

- Per app: `apps/<app>/locale/en/LC_MESSAGES/django.po` (+ `.mo`)
- Project templates (`templates/`) and `nestwerk/`: `locale/en/LC_MESSAGES/django.po`
- The `.mo` files are committed; the Docker image does not need gettext.

## Rules for marking strings

- Templates: `{% load i18n %}`, short texts with `{% translate "…" %}`, texts with variables with `{% blocktranslate with name=x.y %}Hallo {{ name }}!{% endblocktranslate %}` (in `blocktranslate` only simple variables, no attribute access or filters), plurals with `count`.
- Python: `from django.utils.translation import gettext as _` inside functions; `gettext_lazy` for everything evaluated at import time (model fields, `choices`, `verbose_name`, `help_text`, module constants, form labels).
- Named placeholders: `_("%(name)s hat %(punkte)s Punkte") % {...}`; no f-string inside `_()`.
- Context for ambiguous words: `pgettext("Rolle", "Eltern")`.
- **Do not** translate: family members' names, content created by parents (tasks, rewards, custom buttons), log/audit keys, values in the database, URLs, CSS classes, error messages meant only for developers.
- English: short, friendly, kid-appropriate (children from about 6 read along). Neutral between British and American English. Mama/Papa → Mum/Dad only where it is not user content.

## Workflow

```bash
# One app (create the locale/ folder once):
cd apps/<app> && mkdir -p locale && ../../.venv/bin/django-admin makemessages -l en --no-obsolete
# Project templates + nestwerk/ (without the apps):
.venv/bin/python manage.py makemessages -l en --no-obsolete -i "apps/*" -i ".venv/*" -i "tools/*" -i "tests/*" -i "site/*" -i "docs/*"
# Fill in the .po file, then in the same folder:
django-admin compilemessages -l en
```

Check: `msgfmt --check-format -o /dev/null django.po`, no empty `msgstr`, no `#, fuzzy`.
