# Mehrsprachigkeit (Deutsch/Englisch)

🇬🇧 [English](en/i18n.md) · 🇩🇪 **Deutsch**

Entscheidung 45: **Deutsch bleibt Quellsprache** (msgid), Englisch kommt aus `.po`-Dateien.

## Welche Sprache gilt?

1. Eigene Sprache des angemeldeten Benutzers (`Benutzer.sprache`, leer = keine)
2. Geräte-Cookie `nestwerk_sprache` (DE/EN-Schalter auf dem Startbildschirm, `/i18n/setlang/`)
3. Browser-Sprache (`Accept-Language`)
4. Sonst Deutsch (`LANGUAGE_CODE = "de"`)

Ohne Anfrage (Worker, Cron, Push, Mail) gilt die Sprache des Empfängers:
`translation.override(kern.sprache.fuer(empfaenger))` = eigene Sprache, sonst Familien-Sprache
(Einstellung `allgemein.sprache`, bei der Einrichtung aus der gewählten Sprache übernommen).

## Start-Inhalte in der Datenbank

Ränge, Abzeichen, Kategorien, Knöpfe usw. werden deutsch angelegt. Sie sind im Seed-Code mit
`gettext_noop` markiert und werden erst bei der Anzeige übersetzt: Template `{% load sprache %}`
+ `{{ rang.name|uebersetzt }}`, Python `kern.sprache.uebersetzt(text)`. Von Eltern geänderte
Texte sind keine msgid und bleiben unverändert.

## Texte in Ereignissen

Ereignis-Daten werden gespeichert und später für verschiedene Empfänger angezeigt. Darum dort
keine fertigen deutschen Sätze ablegen, sondern msgid + Parameter (z. B. `hinweis_msgid`,
`hinweis_parameter`) und erst beim Rendern übersetzen.

## Wo liegen die Übersetzungen?

- Je App: `apps/<app>/locale/en/LC_MESSAGES/django.po` (+ `.mo`)
- Projekt-Templates (`templates/`) und `nestwerk/`: `locale/en/LC_MESSAGES/django.po`
- Die `.mo`-Dateien sind eingecheckt; das Docker-Image braucht kein gettext.

## Regeln beim Markieren

- Templates: `{% load i18n %}`, kurze Texte `{% translate "…" %}`, Texte mit Variablen
  `{% blocktranslate with name=x.y %}Hallo {{ name }}!{% endblocktranslate %}`
  (in `blocktranslate` nur einfache Variablen, keine Attribut-Zugriffe/Filter), Mehrzahl mit `count`.
- Python: `from django.utils.translation import gettext as _` in Funktionen;
  `gettext_lazy` für alles, was beim Import ausgewertet wird (Modell-Felder, `choices`,
  `verbose_name`, `help_text`, Modul-Konstanten, Formular-Labels).
- Platzhalter benannt: `_("%(name)s hat %(punkte)s Punkte") % {...}`; kein f-String in `_()`.
- Kontext bei Mehrdeutigkeit: `pgettext("Rolle", "Eltern")`.
- **Nicht** übersetzen: Namen der Familienmitglieder, von Eltern angelegte Inhalte (Aufgaben,
  Belohnungen, eigene Knöpfe), Log-/Audit-Schlüssel, Werte in der Datenbank, URLs, CSS-Klassen,
  Fehlermeldungen nur für Entwickler.
- Englisch: kurz, freundlich, kindgerecht (Kinder ab ca. 6 lesen mit). Britisch/amerikanisch
  neutral; Mama/Papa → Mum/Dad nur, wo es kein Benutzer-Inhalt ist.

## Arbeitsablauf

```bash
# Eine App (Ordner locale/ einmalig anlegen):
cd apps/<app> && mkdir -p locale && ../../.venv/bin/django-admin makemessages -l en --no-obsolete
# Projekt-Templates + nestwerk/ (ohne die Apps):
.venv/bin/python manage.py makemessages -l en --no-obsolete -i "apps/*" -i ".venv/*" -i "tools/*" -i "tests/*" -i "site/*" -i "docs/*"
# .po ausfüllen, dann im selben Ordner:
django-admin compilemessages -l en
```

Prüfen: `msgfmt --check-format -o /dev/null django.po`, keine leeren `msgstr`, keine `#, fuzzy`.
